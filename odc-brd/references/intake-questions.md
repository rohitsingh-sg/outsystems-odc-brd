# Intake questions (ask only what is not already answered)

Ask in one batch. Offer a recommended default for each so the user can reply "defaults".

1. **Goal and users:** What problem does the app solve, for whom? Roles and rough user counts?
2. **Scope:** What is in v1? What is explicitly out? Anything to park in a backlog?
3. **App shape:** One app or several (core service, UI apps, theme library)? Anything that must be atomic across modules?
4. **Platform:** Reactive Web, Mobile, or both? Which tenant, portfolio and stage? Existing apps or entities to reuse?
5. **Identity and access:** Real IdP/SSO or test personas for the build? Visibility model (own / team / all)? Approvals?
6. **Mock-ups:** Screens, artifact link or PDF? Layout authority vs spec authority?
7. **Data:** Key entities, reference lists, volumes, retention, data residency, personal data?
8. **Processes:** Main flows, statuses and transitions, approvals, SLAs, notifications (in-app/email).
9. **Integrations:** REST in/out, file storage, payments, AI assist, scheduled jobs and cadence.
10. **Non-functional:** Security, privacy law, audit, performance targets, accessibility, languages, devices.
11. **Branding:** Official assets available? Prototype banner needed?
12. **Testing:** Seed data, who tests, how (browser, curl), acceptance criteria.
13. **Customer-only answers** (rates, legal text, API availability): list as checkboxes in the BRD.
